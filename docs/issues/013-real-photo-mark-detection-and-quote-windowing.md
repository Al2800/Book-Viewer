# 013 - Real Photo Mark Detection and Quote Windowing

Status: open
Area: Quote capture
Priority: high

## Problem

Build 27 improved quote grouping after marked OCR lines had already been selected, but TestFlight review showed that real photographed pages still produce poor quote windows. The product decision after TestFlight review is that OCR-only extraction is not sufficient quality for the core quote-capture experience.

Quote capture is the core functionality of the app. It needs a more sophisticated model-assisted extraction path that can understand marked text on real book pages, including underlines, awkward page curvature, margin marks, broken OCR lines, and visual ambiguity.

Observed user symptom on 2026-06-07:

- A marked page produced an editable quote containing a partial line start: `gle particle, which slowed that light beam`.
- The selected text then crossed awkward OCR fragments and hyphenation: `to the unbeliev- second... does typ- ically slow down`.
- The app did not pick up a vertical margin line in the page margin.

This means the current on-device path can reach the edit screen, but the mark-detection and mark-to-OCR selection seams are too brittle for real camera pages. OCR/local geometry should remain useful context and offline fallback, but it should not be treated as the primary quality ceiling for quote extraction.

## Current Characterization

- `PageMarkDetector` currently detects colored and neutral marks using row runs through the image bitmap.
- Neutral pencil detection is biased toward horizontal underlines.
- `QuoteMarkTextSelector` groups lines once `DetectedPageMark` boxes exist, including margin-line grouping.
- The selector has synthetic vertical margin-line tests, but the detector does not yet have a real-photo vertical margin-line fixture.
- The current pipeline has no optional local-model cleanup stage for already-selected candidate text.

## Suspected Causes

1. OCR/local geometry is too shallow for the product quality bar on real book pages.
2. Vertical margin marks are missed because the detector scans horizontal row runs and filters regions with `rect.width >= 40`.
3. Underline selection may choose the nearest OCR line even when the mark is broken, angled, or under only part of a line.
4. OCR output from photographed pages needs post-processing for hyphenated line breaks and partial line fragments.
5. A hosted vision-language model can likely infer intended marked passages more reliably than deterministic OCR rules alone.

## Model Option

A small local or hosted non-frontier model should be evaluated as a first-class extraction-assist seam. The deterministic OCR/geometry path still matters for context, fallback, testing, and low-cost cases, but the product quality target now assumes model assistance for difficult real pages.

Allowed use:

- clean selected OCR text;
- rank candidate boundaries when deterministic geometry returns multiple plausible windows;
- separate margin note text from quote body.
- inspect a cropped page or crop set and return structured candidates when deterministic confidence is low.

Still not allowed:

- embedding provider secrets in the iOS app;
- returning unstructured prose that the app has to guess how to parse;
- silently dropping low-confidence model results without editable review;
- removing the offline/manual fallback path.

Hosted-model evaluation candidates:

- Qwen2.5-VL 7B Instruct through Hugging Face. This is the preferred first candidate because the user already has Hugging Face Pro and the model is an open image-text-to-text model.
- Qwen2.5-VL 7B AWQ through Hugging Face if the full 7B route is too slow or expensive.
- Mistral OCR-style document endpoint for OCR/bounding-box comparison, not as the final quote selector unless it can identify marks reliably.
- Cloudflare Workers AI vision-capable non-frontier/open models if the existing backend route is retained.

Preferred architecture:

```text
iPhone capture
-> on-device OCR and mark detector
-> if confidence is acceptable: review on-device candidates
-> if confidence is low, no margin mark is found, or user requests higher quality: call BookQuotes proxy
-> proxy calls Hugging Face Qwen2.5-VL 7B Instruct
-> proxy returns normalized quote-review JSON
-> iPhone shows editable review cards
```

Token/security requirements:

- The Hugging Face token must be stored as a backend secret, not in the iOS app.
- The iOS app should continue authenticating to the BookQuotes proxy with its existing session token.
- The proxy should enforce the existing auth, beta/subscription policy, request-size limits, and rate limits before calling Hugging Face.
- The backend route should be configurable with `HF_API_TOKEN`, `HF_MODEL_ID`, and either `HF_PROVIDER` or `HF_ENDPOINT_URL`.
- For the first spike, use Hugging Face routed inference if available. For production, prefer a dedicated Hugging Face Inference Endpoint once model quality is proven.

Backend route candidate:

```text
POST /api/extract-quotes-hf
Authorization: Bearer <BookQuotes session token>
Content-Type: application/json

{
  "image": {
    "mimeType": "image/jpeg",
    "data": "<base64>"
  },
  "onDeviceContext": {
    "ocrLines": [...],
    "detectedMarks": [...],
    "localCandidates": [...]
  }
}
```

The route should return the same normalized quote result shape consumed by `ExtractionReviewView`.

Hosted-model acceptance criteria:

- [ ] The model path is behind a feature flag or explicit fallback setting.
- [ ] The model receives the smallest useful image crop, not automatically every full page.
- [ ] The model returns strict JSON matching the existing review data shape: quote text, mark type, margin note, confidence, and reason.
- [ ] The deterministic on-device path remains the default.
- [ ] A/B fixture results compare on-device-only vs hosted-assist for the same real page photos.
- [ ] The privacy/legal copy states when page images or crops are sent off-device.
- [ ] The app still works without network access by falling back to editable low-confidence local candidates or manual quote entry.
